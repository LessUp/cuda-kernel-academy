# 开发流程

CUDA Kernel Academy 遵循单一、轻量的工作流程，旨在**交付聚焦的修复，避免流程漂移**。

## 原则

- **小而聚焦的变更**
- **按需验证**
- **文档保持诚实**
- **短生命周期分支**
- **最小仪式**

## 标准循环

1. 选择一个边界清晰的改动
2. 以最小但完整的方式实现它
3. 只运行与该改动直接相关的检查
4. 当公共表面变化时，同步更新文档和根目录 changelog
5. 发起聚焦的 PR，并尽快完成合并

## 验证

常用检查：

```bash
pre-commit run --all-files
npm ci
npm run docs:build
cmake --list-presets
```

GPU 相关变更必须在真实 CUDA 机器上完成验证。

## 文档与历史

- 根目录 `CHANGELOG.md` 是唯一保留的 changelog
- GitHub Pages 只保留学习资料、参考文档和模块导读
- 与其保留并行解释，不如删除过时说明

## 收尾偏向

当不确定时，选择以下选项：

- 减少维护负担
- 移除陈旧或低信号内容
- 保持公共表面精致
- 使未来的最终 bug 修复更容易落地
